# Rebuild a reference as native HWP content

Treat a screenshot, PPT export, or reference PDF as visual evidence, not as a page-sized image to paste.
Preserve editable structure for every element that is not inherently raster content.

Read this guidance before constructing the layout. It is also exposed verbatim as the UTF-8 MCP resource `gsg-hwp-beta://reference/native-layout`, so a client that did not receive the plugin skill catalog does not need to search the filesystem or improvise from the tool schema.

1. Call `hwp_analyze_reference_image` once. Its compact result selects `ordinary_layout` or `reference_layout_bulk`, explains the choice in `reason_codes`, exposes verified breakpoints, and includes a valid `draft_reference_layout` when the dense-grid path is appropriate. Do not manually rediscover the analysis file or load all detail sections.
2. Keep independent paragraphs, a small ordinary table, a photo/map/drawing, and a caption as separate paragraph/table/image blocks. Use a reference-layout draft only when a coherent orthogonal grid, partial connectors, repeated style regions, or grid-fixed text dominate the page. Neither path is chosen from a fixed row or column count.
3. Add verified text, merges, and semantic styles to the returned draft without changing its evidence-backed topology. `source_image` and `analysis_id` let the runtime validate and snap the same source before mutation. If one omitted detail is necessary, page only that section through `hwp_get_reference_image_analysis_section`.
4. Call `hwp_preflight_layout` before the first write. A `definite` overflow must be corrected before mutation; a `possible` result returns confirmation or explicit geometry choices and must not trigger arbitrary shrinking. Then send one `hwp_insert_layout` call at the requested `target=after_page` location, or `hwp_append_layout` only at the document end.
5. The specialized path compiles one protocol-10 `ReferenceLayoutBulk` command. The ordinary path remains one protocol-9 `ApplyLayout` batch. Do not expand either path into one call per physical cell.
6. Hancom OCR is optional evidence, not the layout authority. Use the official Hancom OCR service only when small Korean, digits, or rotated text needs help, normalize its returned word or line boxes and confidence into `ocr_words`, and set `ocr_mode="auto"`. High-confidence evidence fills only a text-anchor gap; it never overwrites GPT text or invents borders. Leave `ocr_mode="off"` when model text is already reliable. Official guide: <https://developer.hancom.com/hancomocr/devguide>.
7. The protocol compiles one `ReferenceLayoutBulk` command. C++/ATL applies row and column geometry arrays once, clears all borders once, applies only visible edge regions, applies shared formatting by region, and does not reapply an anchor's text style when the same style region already covers it. It inserts anchored text, performs all merges against one stable topology, then rebuilds and verifies topology once.
8. For an ordinary small table, `border_mode="explicit"` remains available. Up to 50 rows and 50 columns are available, and a narrow spacer or routing segment may be 1 mm. For a physical 1 mm cell, use 1 pt text, 50% line spacing, and zero padding.
9. Start from absent borders. In explicit mode every omitted edge is emitted as `none`, while a declared shared edge is applied consistently to both adjacent cells. Declare only outlines and connector segments visible in the source.
10. Use fill only when the source contains a filled color surface. A connector is a cell border, never a gray or colored filled cell. A blank spacing cell has no fill and no visible border.
11. Merge cells for text boxes, cards, headings, and panels only after grid breakpoints include every required line endpoint. Do not merge across a connector endpoint because one merged-cell edge cannot represent only part of a line.
12. Rebuild titles, body text, bullets, captions, and tables as native paragraphs and cells, reusing the current document's styles instead of imitating fonts manually.
13. Inspect the resulting table dimensions, merges, and cell properties, then render only the changed page with `hwp_render_page` (`CreatePageImage`). Use a low-resolution render or relevant crop while refining and reserve one full-resolution render for final verification. Crop the full-page render to the same computed usable body rectangle before comparing it with `source_image`; page margins must not become false visual differences. Compare positive features and negative space: an extra border, filled connector, clipped text, shifted box, overflow, or distorted raster asset is a failed verification.
14. When comparison identifies only displaced grid boundaries or local font, line-spacing, padding, or border differences, send `reference_layout_patch` with the existing table `target_control_id`. Include only adjacent changed rows or columns and changed style or edge regions. A patch style region must contain any merged cell it touches; it may not start inside or cut through a merge. `ReferenceLayoutPatch` selects and verifies the existing table and never runs `TableCreate`; do not rebuild the whole table for a local render correction.

Use `hwp_insert_layout` with `target=after_page` and `page=N` when the rebuilt page belongs after an existing page. For an interior page, the tool inserts at the next page's start and adds one trailing page break; after the last page it adds one leading page break. This creates exactly one isolated page and does not leave a blank page. Use `target=current` for insertion at the user's collapsed cursor, and use `hwp_append_layout` only for the document end. Keep `auto_fit_row_heights=false` when the reference provides deliberate vertical geometry; automatic fitting may expand a compact grid across additional pages.

When two adjacent cells explicitly request different styles for the same shared border, keep the merge and cell structure and omit only those contradictory shared-edge overrides. The current document's table style then supplies that edge; unrelated outer borders and cell formatting remain explicit.

That conflict-inheritance rule applies to ordinary tables (`border_mode="inherit"`). Reference-layout grids use `border_mode="explicit"`: a visible edge wins over an omitted or explicit no-border neighbor and is mirrored to the other side, while all remaining edges are cleared. If two visible styles conflict, the upper or left cell's edge is canonical; avoid such ambiguity by declaring each source edge once.

Do not invent a figure caption or table title that is absent from the source or the target form.

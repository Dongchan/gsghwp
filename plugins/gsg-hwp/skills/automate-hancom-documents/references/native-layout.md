# Rebuild a reference as native HWP content

This is the structure path: the user wants boxes, connectors, grids, grouped content, or a form in a screenshot, PPT export, or reference PDF turned into editable HWP content. Reading a value from an image and typing it into an existing document is a different job; read that value directly and call the matching write.

Treat the source as visual evidence, not as a page-sized image to paste. The model is the authority for visible text, semantic hierarchy, ownership, repeated-item count, color-to-label correspondence, proportions, and placement.

This guidance is also exposed verbatim as the UTF-8 MCP resource `gsg-hwp-beta://reference/native-layout`.

1. Call `hwp_analyze_reference_image` once with `full_scan=true`. This restores the complete evidence-first path: detected objects, text, lines, breakpoints, tiles, contact sheets, and the evidence overlay must exist before crop coordinates are finalized.
2. Read the source together with the returned overlay and contact sheets. The model decides which elements are independent paragraphs, ordinary tables, editable graphic cells, captions, and separate raster assets; pixel analysis supplies boundary evidence and never decides meaning.
3. Keep photos, maps, drawings, logos, and graphic motifs as individual crops when their pixels are part of the content. Call `hwp_prepare_image_crops` once with every model-chosen semantic rough box. Choose `boundary_mode="tight_raster"` for one rectangular photo or continuous raster panel; its texture boundary must exclude adjacent title pills, body boxes, borders, and neighboring images. Choose `boundary_mode="annotated_group"` for a map, drawing, logo, or motif whose detached labels, callouts, or legend belong to that asset, and loosely include that complete group. Never guess a tight pixel crop or cut through owned visible text. The crop analyzer resolves the final boundary and returns both boxes, confidence, review state, individual PNGs, and a requested-versus-refined overlay.
4. Visually inspect the returned crop files and boundary overlay before preflight. If one item reports `needs_review=true`, use the analysis artifacts to adjust only that rough box once. Each raster block or cell must point to its matching refined crop, never to repeated copies of the full reference page.
5. Preserve every distinct visible relationship in the LayoutPlan, recursively at every nesting level. One visibly distinct fill/border surface owns one native cell or merged region. A group title band, repeated-item subheading pill, and each body box must be separate rows or cells even when adjacent; do not flatten them into differently formatted paragraphs or line breaks in one cell. For the common repeated item shown as one image beside a subheading over body text, build a two-row group: the image cell spans both rows, the right subheading owns the first row, and the right body owns the second row. Additional visibly separate body boxes require additional rows. Before preflight, compare the source's visible text surfaces with the planned non-image cells inside every repeated item; fewer planned cells means the plan is structurally incomplete. Do not combine a heading with its body, a label with an unrelated item, or independently colored/repeated items merely to reduce the row, cell, or image count.
6. Use paragraph/table/image blocks for independent content. Use a reference-layout block only when a coherent orthogonal grid, partial connectors, repeated style regions, or grid-fixed text dominate the page. The choice is semantic and geometric, not a fixed row or column threshold.
7. Analysis never overrides model-observed meaning. If `omissions` names an axis, the missing entries are unknown, not absent; never shrink the model's text, groups, colors, cells, or images to match the compact sample. Page only one necessary detail section through `hwp_get_reference_image_analysis_section`.
8. Hancom OCR is also optional evidence. Use it only for text too small, dense, or rotated to read reliably; it may fill a text-anchor gap but never overwrite model text or invent structure.
9. Call `hwp_preflight_layout` on the completed model plan. Correct a `definite` overflow before mutation; handle a `possible` result with its explicit geometry choices instead of arbitrary shrinking.
10. Execute the declared plan with one `hwp_insert_layout` call at `target=current` or `target=after_page`, or one `hwp_append_layout` call only at the document end. The ordinary path compiles one protocol-9 `ApplyLayout` batch and the reference-grid path one protocol-10 `ReferenceLayoutBulk` command; never expand either into one call per cell, and never insert the full page first to delete, reinsert, move, or crop pictures afterward.
11. Derive breakpoints from visible box edges, text anchors, and connector endpoints. Start from absent borders, declare only visible outlines/connectors, use fill only for visible color surfaces, and never represent a connector as a filled spacer cell. Do not merge across a connector endpoint.
12. Rebuild headings, body text, bullets, labels, captions, legends, and tables as editable paragraphs and cells. Reuse the target document's styles where available instead of imitating fonts blindly.
13. Inspect the created dimensions, cells, merges, fills, text, and image count, then render only the changed page with `hwp_render_page` (`CreatePageImage`). Compare positive features, ownership relationships, crop contents, and negative space against the source body. If a write reports partial mutation or reconciliation required, stop instead of continuing or saving.
14. When only local boundaries, text fit, padding, font, or border details differ, send `reference_layout_patch` against the existing `target_control_id` and render again. Do not delete and rebuild the page for a local defect.

Use `hwp_insert_layout` with `target=after_page` and `page=N` when the rebuilt page belongs after an existing page. It already isolates that page; do not add a second `page_break` block. Keep `auto_fit_row_heights=false` when the reference provides deliberate vertical geometry.

When two adjacent cells explicitly request different styles for the same shared border, keep the merge and cell structure and omit only those contradictory shared-edge overrides. The current document's table style then supplies that edge; unrelated outer borders and cell formatting remain explicit.

That conflict-inheritance rule applies to ordinary tables (`border_mode="inherit"`). Reference-layout grids use `border_mode="explicit"`: a visible edge wins over an omitted or explicit no-border neighbor and is mirrored to the other side, while all remaining edges are cleared. If two visible styles conflict, the upper or left cell's edge is canonical; avoid such ambiguity by declaring each source edge once.

Do not invent a figure caption, table title, group, or relationship that is absent from the source or the target form.
